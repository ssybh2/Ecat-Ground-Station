# v0.3.0：任务修改直接写回与编译

左侧导航现在依次为：**工作台总览 → 首次配置 → 从站与任务 → 执行器调试 → 配置与日志**。

“端口与资源”和“ROS 2 与主站”独立页面已移除。端口参数仍在任务表单内配置，资源冲突仍在写入前校验；ROS_DOMAIN_ID 在执行器调试页设置，主站通过首次配置中的 root 终端手动运行。

## 获取 SN 后怎么做

1. 在首次配置输入真实 SN，点 **进入从站任务配置**。
2. 查看任务页上方的 **当前工作空间**。若从首次配置进入，会自动使用该工作空间；其它工程可点 **选择工作空间**。
3. 添加、修改、删除、排序需要的任务，再点最下方 **应用任务修改**。
4. 软件校验**整个工程**。通过后，自动写入：

   ```text
   <工作空间>/src/soem_bringup/config/config.yaml
   ```

   页面显示明确的写入结果和绝对路径。校验失败会保留原 YAML 并显示具体原因，不会只在内存里静默完成。

5. 点击旁边的 **colcon build（普通用户）**。按钮也会先同步当前编辑，随后以普通用户在该工作空间编译，实时显示日志；可点 **取消编译**。
6. 成功后，软件核对源 YAML 与下面的安装文件 SHA256 一致，并确认编译期间源配置没有改变：

   ```text
   <工作空间>/install/soem_bringup/share/soem_bringup/config/config.yaml
   ```

   只有核对通过才显示“编译成功，安装配置已更新”。源码变化、安装文件缺失或不一致都不会被误报成已生效。

7. 回到首次配置的 root 终端，重新运行主站，加载新配置。编译本身不热更新运行中的主站，也不自动驱动执行器。

## 保存、备份与恢复

- 每次替换旧 YAML，先备份到 `<工作空间>/.ecat-groundstation/config-backups/`；内容没有改变时不重复备份。
- 完整工程自动保存到 `<工作空间>/.ecat-groundstation/project.ecat.json`，包括型号、任务和工作空间设置。下一次启动会恢复上次已应用的工程。
- 从其它 JSON 打开的工程，原文件仍可通过“保存项目”更新，工作空间的自动快照另行保留。
- 示例工程默认没有绑定真实工作空间，避免编辑示例时覆盖机器人的现有配置。应用按钮会提示先选择工作空间。
- 应用过正式任务后，再次创建本软件管理的 bringup 包会保留正式 YAML，不会退回 `sn2228293` 的首次发现模板。

## 创建 bringup 的自动检查

**Creat bringup package** 现在每次都会在后台重新检测当前实时内核、物理核心隔离和实际启动参数。检查通过便直接生成，不要求用户先返回其它页点“确认”。只有缺失设置时才指出具体项目，例如 `nohz_full` 或 `irqaffinity`，避免使用上次窗口留下的空状态。
