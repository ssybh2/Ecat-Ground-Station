# v0.2.1 EEPROM 部分写入修复

两次失败不是管理员认证或 BIN 路径问题。读取本机 root 专属备份后确认：

| 操作 | 初始状态 | 写入后与 Large PDO 镜像的差异 |
|---|---|---|
| 第一次 | 原始标准版镜像，产品代码 3 | 产品代码已变为 4，但仍有 14 个字节未更新 |
| 第二次 | 与第一次回读完全相同 | 仍有 7 个字节、5 个 16 位字未更新 |

第二次差异字节偏移为 `0x00a0`、`0x00a1`、`0x00cc`、`0x00da`、`0x00db`、`0x00e9`、`0x00f7`。因此，写入实际发生了，但整个镜像尚未一致，v0.2.0 的最终比对正确地阻止了“成功”提示。

原 `eepromtool.c` 在循环中调用 `ec_writeeepromAP()` 后忽略其返回值，也没有逐字回读验证；某个字没有落盘时仍继续写后面的字。SOEM 1.4 的 `ecx_eeprom_waitnotbusyAP()` 在 WKC 为 0 时也可能因为状态值被清零而误判 ready。旧上位机只做最终比对，不补写，因此只能重复得到部分写入的失败结果。现有证据不能单独判断底层偶发失败来自 EEPROM 时序、NACK 还是链路调度，修复版会记录这些诊断信息。

## 新逻辑

点击刷写仍由一个按钮完成：

1. **普通用户**使用工作空间中已检出的 SOEM 源码构建本软件的 `eeprom_verified` 工具，缓存在 `~/.cache/ecat-groundstation/eeprom/`。不替换或修改原仓库的工具、SOEM 源文件；需要 `cc` / `gcc`（`build-essential`）。
2. 系统授权后先读取并备份原 EEPROM；每个完整读操作要求两次数据相同。
3. 只写不一致的 16 位字，跳过已经一致的字，减少重复写入。
4. 每次检查 EtherCAT working counter、EEPROM busy/error 状态；增加等待时间，并回读当前字确认。
5. 当前字最多尝试 8 次，失败即停止；记录字节偏移、期望值、实际值、EEPROM 状态和重试次数，不继续盲写。
6. 完成后再做两次一致的全镜像读取，以及独立的最终镜像比对。只有全部一致才报告成功。
7. 写入失败后可再做一次**只读**回读，保存 `failure.json`，明确还剩哪些字节。每次操作日志自动保存到 `~/.local/share/ecat-groundstation/logs/`，关闭窗口后仍可查看。

重新打开软件会恢复已选的 Large PDO 类型、网卡、镜像和从站链位置，避免重试时意外退回标准版默认值。

新增 **只读诊断 / 对比镜像** 按钮，只读当前板卡并比较选中镜像，不执行 EEPROM 写命令。它可用于确认重试前的实际状态。备份仍位于 `/var/backups/ecat-groundstation/eeprom/`；只读报告位于 `/var/backups/ecat-groundstation/eeprom-diagnostics/`。

系统认证窗口中的密码仍由 polkit 处理，日志不包含管理员密码。

## 验证与边界

真实的本机 SOEM 源码编译已通过。自动化测试编译并运行同一份 C 程序，使用不连接硬件的 ESC 模拟器，复现了上述七个差异偏移和五个字：

- 模拟写命令被 ACK 但内容未变化，三次重试后恢复；只写五个不同的字，其余 1019 个字不写。
- 模拟永久失败，恰好在 8 次尝试后报错退出，不报告成功。
- 镜像已一致时不做任何 EEPROM 写操作。
- 只读诊断不发 EEPROM 写命令。
- WKC 丢失不再误判为成功。

此次排查读取了两次历史备份，未对真实板卡重新执行写入。软件修复经过模拟回归验证，板卡是否完全恢复需要在修复版点击刷写并看到最终全量校验通过。成功后再按提示断电重上电。
