# v0.4.4 H750 烧录与轻量本地编译

在 **首次配置 → 3 H750 固件** 中有两条独立路径：

1. **选择本地固件并烧录**：默认页签，直接选择电脑上已有的 ELF / HEX / BIN，再检测 ST-Link、烧录和校验。不需要源码工作空间、ARM 编译器或 C++ 库。
2. **本地源码编译（可选）**：选择自己的 H750 CMake 源码工作空间，点击 **编译H750固件**。编译成功后点击同一行的 **烧录**，直接使用最近一次成功编译的 ELF；自动检测 ST-Link，无需再选择固件路径或确认。未连接时提示；多个设备时选择具体 ST-Link；管理员授权仍由系统处理。烧录前校验记录中的 SHA256，之后执行 halt、擦写与回读校验，并显示结果。

编译不会自动选择或替换烧录文件，改变源码设置、重新编译、编译失败也不会修改已选择的固件。独立烧录窗口沿用用户已经选定的文件。

编译页 **烧录** 只使用当前构建设置对应的成功产物，编译失败或更改设置后不可用；不使用手动烧录页的固件。仍可通过 **选择编译产物用于烧录…** 手动选择 ELF / BIN / HEX。

可自定义：

- 源码路径和输出路径；输出路径须在源码目录之外。
- 完整 ARM 工具链的 `bin` 目录；留空使用系统 PATH。
- CMake 工具链文件；留空使用源码内的 `cmake/gcc-arm-none-eabi.cmake`。
- CMake 构建目标，默认 `EcatV2_AX58100_H750_Universal`。
- Release、Debug、MinSizeRel 或 RelWithDebInfo。

**获取 / 检查 H750 源码** 可克隆 [官方源码](https://github.com/AIMEtherCAT/EcatV2_AX58100_H750_Universal)，初始化 SOES 子模块；已经存在的源码保留用户修改，也支持检查不含 Git 元数据的本地源码。

编译使用普通用户，在独立源码快照及构建目录中运行 CMake / Make，不修改原工程。当前尝试失败时不选择历史 ELF。成功后校验 ARM ELF32、加载范围及 H750 内部 Flash 边界，生成 BIN、HEX 和带 SHA256 的 manifest。构建结果与设置会保存，重启可恢复；进入软件时仍默认显示手动烧录页，不自动选择历史编译文件。源码后续修改需要重新编译。

编译不会触发烧录。原有的自选 ELF/HEX/BIN、独立烧录窗口、ST-Link 和 MCU 检测、halt、擦写和回读校验均保留。编译产物烧录前仍检查 SHA256。

## Debug 与 128 KiB Flash

Debug 保留调试符号，使用 `-Os -g3` 适配 H750 的 128 KiB Flash；部分变量可能被优化。目录编译选项也应用于 HAL / FreeRTOS 子目录，避免上游工具链无条件设置 `-O0` 导致固件超限。构建类型仍为 Debug，不切换为 Release，也不扩大 Flash 边界。

对 SHA256 为 `5d172f21167dbe121863da482307c29ca5cc63851a6e34dfef14f7e2e0a25c33` 的已知上游 `Application/task_defs.hpp`，若工程没有提供基类实现，在编译快照中将 `CanRunnable::can_recv` 和 `I2CRunnable::i2c_recv` 声明为纯虚接口，修复缺少虚函数表的链接错误。已经修改的头文件及已经提供基类实现的自定义工程不自动改写。

这些适配只修改独立编译快照。每个修改文件的原始及修改后 SHA256、修改原因都记录在 `manifest.json` 的 `snapshot_adaptations` 中；原始源码目录不变。

本次实际 Debug 验证中，原 `-O0` 构建达到 215,012 B 并产生虚函数表错误，修复后 Flash 为 96,200 B，ELF 保留 `.debug_info`，BIN / HEX 均已生成。没有执行烧录。

151 项测试通过，包含 `-O0` 下的真实 C++ 虚函数表错误复现与修复验证，以及 Debug 优化选项对 ARM 子目录目标生效的实编检查。结果见 [h750-debug-validation.json](../artifacts/h750-debug-validation.json)。

## 依赖

H750 官方固件使用 C++20。v0.4.2 已从所有安装方案中移除 `libstdc++-arm-none-eabi-newlib`，不会安装或下载这个约 347 MB 的多架构包。

已有 Ubuntu 22.04 ARM GCC 10.3.1 时，编译按钮自动准备轻量环境：

- C++ 头文件约 1 MB，优先复用 APT 缓存；缺失时仅以普通用户下载这一头文件包，验证 APT 元数据中的 SHA256，再解压到用户目录，设有 2 MB 大小上限。
- 从固定的 GNU GCC 提交获取所需源码和许可证，共约 100 KB；每个文件按内置 SHA256 校验。
- 仅为 Cortex-M7 / FPv5-D16 / hard-float 构建所需 GNU 组件，生成约 31 KB 的运行库及 nano 链接版本，不构建其它架构。
- 源码、头文件及运行库均缓存，后续无需重复下载或编译运行库。系统工具链和原固件工程不被修改。

**安装 H750 轻量基础依赖** 仍可补齐编译器、Make、Newlib 等基础工具；全新机器上基础 ARM 编译器与 C 库约 94 MB，不能把它们算进上述约 1.1 MB 增量。IMU 的精简依赖和直接选择本地固件烧录的方式保持不变。

轻量模式适用于官方 H750 工程关闭异常、RTTI、线程安全静态初始化的配置；没有编写替代 STL 实现或空函数占位。其它编译器版本或需要更多 C++ 运行时功能的自定义工程仍可选择完整 ARM SDK，缺少功能时明确报错，不回退到大型下载。
