# v0.4.0 H750 本地编译

在 **首次配置 → 3 H750 固件** 中，填写或选择 H750 CMake 工程根目录，然后点击 **编译H750固件**。

可自定义：

- 源码路径和输出路径；输出路径须在源码目录之外。
- 完整 ARM 工具链的 `bin` 目录；留空使用系统 PATH。
- CMake 工具链文件；留空使用源码内的 `cmake/gcc-arm-none-eabi.cmake`。
- CMake 构建目标，默认 `EcatV2_AX58100_H750_Universal`。
- Release、Debug、MinSizeRel 或 RelWithDebInfo。

**获取 / 检查 H750 源码** 可克隆 [官方源码](https://github.com/AIMEtherCAT/EcatV2_AX58100_H750_Universal)，初始化 SOES 子模块；已经存在的源码保留用户修改，也支持检查不含 Git 元数据的本地源码。

编译使用普通用户，在独立源码快照及构建目录中运行 CMake / Make，不修改原工程。当前尝试失败时不选择历史 ELF。成功后校验 ARM ELF32、加载范围及 H750 内部 Flash 边界，生成 BIN、HEX 和带 SHA256 的 manifest，再自动填写烧录文件路径。构建结果与设置会保存，重启可恢复；更改构建设置会清除旧的自动填入路径。源码后续修改需要重新编译。

编译不会触发烧录。原有的自选 ELF/HEX/BIN、独立烧录窗口、ST-Link 和 MCU 检测、halt、擦写和回读校验均保留。编译产物烧录前仍检查 SHA256。

## 依赖

H750 官方固件使用 C++20，与 IMU 的 C 工程不同，需要 ARM C++ 头文件和标准库。可以选择已有完整 ARM SDK 的 bin，也可以手动点击 **安装 H750 编译依赖**。此选项单独按需安装 ARM C++ 依赖；Ubuntu 22.04 对应库下载约 347 MB。编译按钮只检查依赖，不会自动下载这个大包，IMU 精简依赖保持不变。

## 验证范围

141 项回归测试通过，覆盖自选源码与目标、路径含空格、原源码保留、真实 ARM CMake 构建并生成 ELF/BIN/HEX、未完成构建不选用旧产物、界面自动填写与手动烧录保留、修改设置清除旧自动路径，以及缺少 C++ 库时提前停止。

真实编译测试使用最小 H750 C 工程验证构建链路。官方完整源码也完成了克隆和 SOES 初始化，但本机缺少 ARM C++ 头文件及标准库，因此依赖检查明确阻止完整工程编译，未为验证重新下载大包；未执行实物烧录。
